## Layout (Nebbinator only)

- `Nebbinator.toc`: Interface 16001 - Forever only since 21 Oct 2026 (Arn: "no more tbc support"). It holds the load order and is the only place the version lives (`## Version`, 4.0.0 = the Forever rebuild, 5.0.0 = Forever 1.0). `NS.VERSION` reads it through `GetAddOnMetadata`, and `dev/release.ps1` and every dev suite read the TOC too. SavedVariables: `NebbinatorDB` only (the TBC-era `NubbinatorDB` and its migration are gone). `## OptionalDeps: BiSTheme`. Load order: `Libs` (Console, Options, Minimap, Settings, LibBiSComm) → `Core\Util`, `Init`, `Fence`, `Message`, `Responders`, `Team`, `Stats`, `Scout` → `API.lua` (`NebbinatorAPI` v2, read-only plus Open; its header is the doc) → `UI\Kit`, `Cards`, `Window`, `SendBar`, `Desk`, `Options`, `Pages\*` (Recruit, Message, Replies, Team, Stats, About), `Minimap`.
- **The guild (21 Oct 2026, the 4.0 rebuild).** `Core/Fence.lua`: NebbinatorDB is the ACCOUNT's, so everything a guild owns (`F.KEYS`: needs, raid times, Discord, desk, team, stats, scoutSeen...) is one BOOK per guild ("Name-Realm", "-" without one); only the current guild's is live in `NS.db`, the rest parked in `db.guilds`. Until GetGuildInfo answers, `F.Ready()` is false and Team/Scout do nothing. `Core/Team.lua`: LibBiSComm GUILD mod "NEB" - REC (a desk row changed; officers keep class/level/note, members only who is a prospect; since 6 Nov only WORKED rows - a "new" row from a whisper stays on your own desk, a REC "new" is refused, the login tidy clears old "new" rows, and other characters of this account (`db.mine`, written at each login) are never recruits), NEEDS (officers only, newest stamp wins), ASK at login; officers = guild ranks 0..`db.officerRank` (BiS Guild's rule). `Core/Scout.lua`: GROUP_ROSTER_UPDATE, settled `S.SETTLE` s, a card per needed class not in the guild (big + sound guildless, small guilded, "nudge them" for a prospect), once a week each. `Core/Stats.lua`: posts and the whispers they brought (15 min window), the post-again reminder. `UI/Cards.lua`: SURVIVOR's rally band - draining cards and filling working bars, one OnUpdate only while one is up.
- Every file starts with `local ADDON, NS = ...`, and each module hangs off `NS` (`NS.Util`, `NS.Message`, `NS.Responders`, `NS.Kit`, `NS.UI`, `NS.Minimap`). `NS` is exposed as `_G.Nebbinator`. Files reach sibling modules through `NS.*`, never a bare local, because later files would not exist yet when an earlier one loads.
- `Core/Init.lua` (425 lines): the namespace, the DB, slash commands and boot. Sections are split by `----` banners:
  - Defaults (`NS.Defaults`, also used by the fence for a new guild's book) and `NS.DB_VERSION` 5 (in `db.dbVersion`). `NS:LoadDB` fills in new keys over a 3.x save, upgrades the old fixed logs address, and opens a pre-4 save on the Desk tab.
  - FOREVER 1.0 (5.0.0, 7 Nov 2026): a NEW install (no table or an empty one, decided before any merge) gets the quiet Defaults - the desk on; the bell (`autoReply.playSound`), the party scout (`scout`) and the post reminder (`remind` 0) off, auto-reply and lead finder off as before. A save with `dbVersion` < 5 first gets `NS.FROZEN_V4` (scout true, remind 15, autoReply.playSound true) written into any of those keys it lacks - the value 4.x read for a missing key - then is stamped 5, so it runs once. No per-character mirror exists, so a client that hands back no NebbinatorDB for an existing user looks new (quiet).
  - Toggles (`NS.TogglePreview`, `NS.ToggleAutoReply`, `NS.SetChannels`, `NS.SetDiscord`, `NS.ToggleMinimap`, `NS.ResetWindow`). A slash command and a UI control must both call these functions, never write the key themselves.
  - The shared BiS channel (`NS.Comm`, on the embedded LibBiSComm-1.0)
  - Slash command `/bisn` (since 12 Oct 2026, the family's `/bis*`); `/nb`, `/ns`, `/nebbinator` kept as aliases (SLASH_NEBBINATOR2-4, no gaps: the client stops at the first missing number). Subcommands: `show`, `r`/`desk`, `book` (steps between the desk and the last other page), `config`/`options`/`settings`, `preview`/`test`, `reply`, `scout`, `channels <a, b>`, `discord <link>`, `minimap`, `reset`. SHORT WORDS (6 Nov 2026): every word over 4 letters has one of 4 or fewer (`opt`, `test`, `rep`, `sct`, `chan`, `disc`, `mini`, `rst`); `NS.SLASH_WORDS` turns any typed word into its command (`NS.SlashWord`) before the handler picks, and the help prints the short one in brackets.
- UI rules (6 Nov 2026): every clickable thing pops under the mouse at `K.HOVER` (0.32) wash + accent edge or left bar (`K.RowHover` for rows), label to `ink`. The version mark (`UI.VersionMark`, deploy stamp `NS.BUILD` from `X-BiS-Build`) sits faint at the foot of the rail, never in the header bar. The window's text is 10 pt and up, so no SetScale.
  - Events: `ADDON_LOADED`, then `PLAYER_LOGIN` → `NS:Initialize()`, then `PLAYER_LOGOUT` → `NS.Comm.Save()`
- `Core/Util.lua`: has no side effects. Contains the palette (`NS.T`, which uses `BiSTheme` when loaded and otherwise the same hex values inline), the class/spec table `NS.CLASSES` (its order is used everywhere; each spec has a `role`), `NS.SOUNDS` (sound KIT ids - Forever plays nothing from a file path) and string helpers.
- `Core/Message.lua`: template tokens (`{guild}`, `{discord}`, `{nextraid}` from `BiSGuildAPI.RaidNight()`, ...), rendering, channels, and a chat-safe split. A public channel / SAY / YELL takes ONE part per click (`M.CLICK_ONLY`, `M.pending`, the button says "2/2"); `M:Locked()` = `C_ChatInfo.InChatMessagingLockdown`: a post refuses, a whisper is held (`M.queue`, `M:Flush`).
- `Core/Responders.lua`: guild roster (and `guildRanks` for Team), incoming whispers, a passive lead finder, auto-reply with a rate cap (class-aware, launch-day `busy`), guild news (joined/declined), the desk's tidy (`R:Tidy`), and a `/who` lookup (needs a real button click). Every desk change that matters goes to the guild through `R.Share` → `Team.Changed`.
- `UI/Kit.lua` (487 lines): `NS.Kit`, flat drawing primitives with no Blizzard templates or backdrops. Holds the primitives, flat button, text input, scrolling, multi-line box and copy box. Everything lives in one table because of the Lua 5.1 limit of 200 locals per chunk.
- `UI/Window.lua`: `NS.UI`, the single window (`NebbinatorFrame`), FIXED at 820x574 (1.43:1) since 4.0: header, the tab rail (`UI.PAGES`: Desk, Team, Stats, Recruit, Message, Replies, About) and the page beside it. The desk page is edge to edge (`UI.EDGE_TO_EDGE`). `ToggleBook` survives only as "desk <-> last other page". Controls write the same saved variable as the slash commands, through the same function.
- The other `UI/` files:
  - `Desk.lua`: the Desk page - the queue of responders, one row each, with filters; the list takes the room the page has left (`UI.MAX_ROWS` is computed) and scrolls. The row being served opens up.
  - `SendBar.lua` (217 lines): one send button per channel, each with a cooldown clock. Right-click hides a channel.
  - `Options.lua`: the option list for the shared `Libs\BiSTheme\Options.lua` window. Every `set` calls the function the slash command already uses. `UI:RegisterSettingsPage()` (called at login after `UI:Initialize`) registers "BiS> Nebbinator" under the one BiS> entry in the game's options (`Libs\BiSTheme\Settings.lua` minor 2): `window` = this options window, which the page NEVER re-parents or shrinks - the page shows the status line and a button "the options window" that closes the game's options and shows it as it always was (a dashboard via `build` comes later), `open` = the desk, `status` = `UI:SettingsStatus()` ("3 new waiting - bell off - scout off - auto-reply off"), api = NebbinatorAPI.
  - `Minimap.lua`: the family's button (`BiSTheme.Minimap` minor 5, frame `BiSMinimapNebbinator`): `onLeft` = the window ("left-click  the window"), right = `onRight` = `UI:ToggleOptions()`, the own options window as a toggle (right-click again closes it), never the game's options (Arn, 7 Nov live: "we keep them opening how they used to"); tooltip "right-click  options". No menu since 5.0.0 (its switches are option rows, its pages the window's tabs); the star brightens while somebody new waits.
- `UI/Pages/`: the other tabs. `Recruit.lua` covers needs, raid times and the preview. `Message.lua` covers guild details, templates and tokens. `Replies.lua` covers the four quick replies and the auto-reply. `Team.lua`: the guild's needs (and an officer's Send to the guild) and the guild's list. `Stats.lua`: what works, and the reminder's setting. `About.lua` is the about page.
- `Libs/`: embedded copies of `BiSTheme/Console.lua`, `BiSTheme/Options.lua`, `BiSTheme/Minimap.lua`, `BiSTheme/Settings.lua` and `LibBiSComm-1.0` (the suite holds them byte-equal to the canonical files).
- `dev/harness.lua` (478 lines): the real stub library, not a shim.
  - Paint setters (`SetColorTexture`, `SetVertexColor`, `SetTextColor`, `SetFont`) throw an error unless they get real numbers, and they record what they were given.
  - `SetPoint` is recorded for layout checks.
  - Any global outside `ALLOWED_GLOBALS` fails the run.
  - `H.TOC(root, "Nebbinator.toc")` turns the TOC into the load list, and `H.Load` runs each file as `chunk("Nebbinator", NS)`.
- `dev/tests.lua`: the main suite, `lua5.1 dev/tests.lua`. It loads files in TOC order and seeds a 3.x beta `NebbinatorDB` so the upgrade runs every time. The harness models a party/raid (`H.raid` entries with class, guild, role; `H.inParty`/`H.inRaid`), the guild roster with ranks (`H.guild`), this character's guild (`H.myGuild`, `H.guildLate`, `H.myGuildRealm`). `NEB=<path>` runs it against a scratch copy, which is how you check that a stub still catches a deliberately broken copy (the fence section fails with the swap disabled).
- `dev/options.lua` (199 lines): tests `Libs/BiSTheme/Options.lua` on its own, from a hand list (`OPT=` overrides the root). It expects `T.OPTIONS_MINOR` to be 2.
- `dev/theme.lua` (30 lines): checks the palette both without and with BiSTheme. It needs the real `../BiSTheme/BiSTheme.lua` next to this checkout (`BISTHEME=` overrides).
- `dev/README.md`: how to run the suites, why the stubs are strict, and a table of past test-breaking mutations.
- `dev/release.ps1`: zips the addon into Downloads and uploads it to CurseForge project 1683356 (unlisted).
  - Switches: `-Type alpha|beta|release` (alpha by default), `-ZipOnly`, `-Force`.
  - It sends the top entry of `CHANGELOG.md` and writes a `.uploaded` marker so a version goes up only once.
- `.github/workflows/check.yml`: calls the reusable `bisdev` workflow with `addon: Nebbinator`.
- `_backup_v1/` and `_backup_v2/`: old UI and Core, kept in git but not listed in the TOC, so they never load. Leave them alone.
- `Claude outputs/`: holds an old `Nebbinator-3.0.0.zip`, which git ignores because of `*.zip`.
